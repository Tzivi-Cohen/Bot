# 📚 StudyMate AI

בוט לימודי מבוסס RAG ‏(Retrieval-Augmented Generation): שואלים שאלה בשפה חופשית, והבוט עונה **רק על סמך מסמכי הלימוד שבמאגר**, ומציג את המקורות שעליהם התבססה התשובה.

נושאי המאגר: Python, ‏C, ‏C++, מבני נתונים ואלגוריתמים, Arduino, ‏STM32, אלקטרוניקה ומערכות משובצות (Embedded Systems).

---

## 1. מטרת המערכת

מודל שפה אינו מכיר את חומרי הלימוד שלי, ואם יענה בלי מקור הוא עלול להמציא. ב־RAG המערכת קודם **מאתרת** את הקטעים הרלוונטיים במסמכים, ורק אז מעבירה אותם למודל יחד עם השאלה. כשאין במסמכים מידע מספיק, הבוט עונה:

> לא מצאתי מידע מספיק במסמכים כדי לענות על השאלה.

## 2. ארכיטקטורה

```
שלב הכנה (פעם אחת לכל מסמך)
knowledge_base/ + uploads/ ──► חילוץ טקסט (PDF/DOCX/TXT)
   ──► SentenceSplitter (512 טוקנים, חפיפה 50) ──► Embeddings (text-embedding-3-small)
   ──► VectorStoreIndex + ChromaVectorStore ──► ChromaDB מקומי בתיקייה storage/chroma

שלב שאלה
שאלה ──► חיפוש סמנטי ב־ChromaDB (Cosine, 20 מועמדים)
     └──► חיפוש מילות מפתח BM25 מקומי (20 מועמדים)
   ──► איחוד דירוגים (RRF) ──► 3 המקטעים המובילים
   ──► פרומפט "ענה רק מהמקורות" ──► gpt-4o-mini ──► תשובה בעברית + מקורות
```

## 3. הבחירות הטכנולוגיות (נקודות ההחלטה מדף התרגיל)

1. **Vector DB – ‏ChromaDB**, כפי שלמדנו בכיתה, דרך `ChromaVectorStore` של LlamaIndex. ChromaDB רץ מקומית (`PersistentClient`, קובצי SQLite בתיקייה `storage/chroma`) עם מרחק Cosine. בהפעלה מחדש האינדקס נטען מהדיסק, בלי ליצור Embeddings מחדש.
2. **ספרייה – LlamaIndex**, כנדרש: טעינת מסמכים, `SentenceSplitter`, `VectorStoreIndex`, Retriever ושמירה לדיסק.
3. **אופן החלוקה – לפי טוקנים**, תוך שמירה על גבולות משפטים, 512 טוקנים למקטע. חלוקה לפי משמעות מדויקת יותר, אבל דורשת Embeddings כבר בשלב החלוקה ולכן יקרה יותר. חלוקה לפי מילים אינה מתאימה, כי מגבלות המודל נמדדות בטוקנים. 512 נמצא בטווח שהחוברת ממליצה עליו כנקודת התחלה (300–600).
4. **חפיפה – כן, 50 טוקנים (כ־10%).** החפיפה שומרת הקשר כשמשפט חשוב נחתך בין שני מקטעים. חפיפה גדולה יותר הייתה מנפחת את האינדקס בכפילויות.
5. **ספק API – OpenAI**, בגלל העלות הנמוכה של המודלים והשילוב המוכן ב־LlamaIndex. המפתח נשמר בקובץ `.env` מקומי שאינו עולה ל־Git.
6. **Top K = 3.** שלושה מקטעים נותנים למודל מספיק הקשר בלי רעש. החוברת מזהירה ששליפת יותר מדי מקטעים יוצרת הקשר ארוך ורועש.
7. **מודלים:** `text-embedding-3-small` ל־Embeddings – זול ותומך בעברית; `gpt-4o-mini` לתשובות – זול ומספיק טוב לניסוח תשובה מתוך הקשר נתון. ‏`temperature=0` לתשובות עובדתיות, ותקרה של 600 טוקנים לתשובה.
8. **הרחבת שאלה – ללא LLM.** הרחבה באמצעות LLM מוסיפה קריאה בתשלום וזמן תגובה לכל שאלה, ועלולה לשנות את כוונת השאלה. במקומה יש הרחבה **מקומית**:
   - מיפוי שמות נושאים בעברית ובאנגלית (פייתון ↔ Python, ארדואינו ↔ Arduino, סי פלוס פלוס ↔ C++).
   - מילון מונחים שנלמד מהחומר עצמו: החומר כותב מונח בעברית ואחריו את המונח באנגלית בסוגריים, למשל "סריקות עץ (Tree Traversals)", והזוגות נאספים אוטומטית מהמקטעים.
9. **צורת החיפוש – היברידית.** חיפוש סמנטי ב־ChromaDB וחיפוש מילות מפתח BM25 שרץ מקומית על טקסט המקטעים. כל שיטה מחזירה 20 מועמדים, הדירוגים מאוחדים בשיטת Reciprocal Rank Fusion ‏(k=60), ולמודל נשלחים 3 המקטעים המובילים. החיפוש ההיברידי נוסף בעקבות בעיה שהתגלתה בבדיקות (ראו בעיה 1 בפרק 8).

## 5. שימוש במערכת

- **ספריית הלימוד:** ניווט בין נושאים ומסמכים, ותצוגת מסמך עם כותרות, רשימות ובלוקי קוד משמאל לימין. אפשר לחפש לפי נושא, שם קובץ או תוכן, בעברית ובאנגלית.

## 6. התקנה והפעלה ב־Windows

**דרישות:** Python 3.13, חיבור לאינטרנט ומפתח OpenAI. כל החבילות, בגרסאות קבועות, מופיעות ב־`requirements.txt`.

```powershell
git clone https://github.com/Tzivi-Cohen/Bot.git
cd Bot
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

**הגדרת המפתח:** מעתיקים את `.env.example` לקובץ בשם `.env`, ומדביקים את המפתח המלא אחרי הסימן `=`:

```
OPENAI_API_KEY=sk-proj-...
```

אסור להעלות את `.env` ל־GitHub. הוא כבר מופיע ב־`.gitignore`.

**הפעלה:**

```powershell
streamlit run app.py
```

אם `Activate.ps1` חסום במחשב, אפשר להריץ ישירות: `.venv\Scripts\python -m streamlit run app.py`.

בהפעלה הראשונה המסמכים שב־`knowledge_base/` עוברים אינדוקס (נוצרים להם Embeddings). בהפעלות הבאות האינדקס נטען מהדיסק.

**בדיקות:**

| מטרה | פקודה | הערה |
|---|---|---|
| בדיקות אוטומטיות | `python -m pytest` | לא פונות ל־OpenAI |
| הדגמת הממשק | `streamlit run tests/ui_demo_app.py` | מודלים מזויפים, ללא קריאות API |
| בדיקה מול OpenAI | `python tests/manual_api_check.py --strict` | מריץ את 5 שאלות הבדיקה (פרק 7). בתשלום – מבקש אישור לפני השליחה |

**פתרון תקלות:**

- **שגיאת SSL ‏(`CERTIFICATE_VERIFY_FAILED`):** תוכנת אנטי־וירוס שבודקת תעבורת HTTPS עלולה להחליף את אישור האבטחה. הפרויקט משתמש בחבילה `truststore`, כך ש־Python מאמת אישורים דרך מאגר האישורים של Windows. אין לבטל אימות SSL.
- **"המפתח נראה לא שלם":** המפתח הודבק חלקית, או שיש בו רווחים או מרכאות. המערכת אינה מציגה את המפתח עצמו.

## 8. בעיות שהתגלו במהלך הפיתוח ופתרונן

### בעיה 1: התשובה נמצאת במאגר, אבל הבוט ענה "לא מצאתי"

**הבעיה:** בבדיקה הראשונה מול OpenAI, שתיים מארבע השאלות קיבלו "לא מצאתי מידע", למרות שהתשובות כתובות במסמכים: ההבדל בין `/` ל־`//` ב־Python, ושאלה על רשימת אתחול בבנאי שנוסחה במילים אחרות מהמסמך.

**הגורם:** החיפוש היה סמנטי בלבד. בדיקת הדירוג המלא הראתה שהמקטע הנכון היה במקום 4 ובמקום 5 – מחוץ ל־3 המקטעים שנשלחים למודל:
- בשאלה הראשונה ההסבר על `/` ו־`//` נמצא בסוף מקטע שעוסק בעיקר בטיפוסים ובהמרות, ולכן מקטעים אחרים דורגו גבוה יותר.
- בשאלה השנייה הניסוח שונה מהמסמך, והשאלה אינה משתמשת במונח "Member Initializer List". ציוני הדמיון היו נמוכים וצפופים, ובמקום הראשון נשלף מקטע על קבלים.

**הפתרון:** חיפוש היברידי – חיפוש סמנטי יחד עם חיפוש מילות מפתח BM25 מקומי, ואיחוד הדירוגים בשיטת RRF. Top K נשאר 3, ולא נדרשו אינדוקס מחדש או קריאות API נוספות. בבדיקה החוזרת ארבע השאלות עברו (4/4, לעומת 2/4 לפני התיקון).

### בעיה 2: שאלות חופשיות בעברית לא מצאו את החומר

**הבעיה:** שאלות כמו "מהו בנאי?" או "אני לא מבינה את עניין הסריקות בעצים" קיבלו "לא מצאתי מידע", למרות שהחומר קיים.

**הגורם:** החומר כתוב עם מונחים באנגלית (Constructor, ‏Tree Traversals), והמשתמשת כותבת בעברית ובנטיות שונות ("הסריקות", "בעצים" לעומת "סריקה" ו"עץ" במסמך). חיפוש מילות המפתח השווה מילים מדויקות בלבד, ומילים שמתארות את הבקשה ולא את התוכן – כמו "הסבר", "מבינה" ו"מידע" – משכו מקטעים לא קשורים.

**הפתרון (מקומי, בלי LLM ובלי עלות):**
- מיפוי שמות נושאים בין עברית לאנגלית, ומילון מונחים שנלמד אוטומטית מהחומר עצמו – לא רשימה ידנית של מילים בודדות.
- זיהוי נטיות בעברית: אותיות שימוש, יחיד ורבים ואותיות סופיות.
- הסרת ניסוחי בקשה ("אני לא מבינה את...", "הסבר לי...") מטקסט החיפוש בלבד – המודל עדיין מקבל את השאלה המקורית.

בבדיקה מול האינדקס האמיתי, הקובץ הנכון נמצא ב־3 התוצאות הראשונות ב־36 מתוך 36 שאלות מכל הנושאים, כולל ניסוח לא מדויק ושאלות המשך.

### בעיה 3: כשל רשת הוציא מסמך מהאינדקס

**הבעיה:** בזמן עדכון של קובץ Python שתוקן, החיבור לאינטרנט נפל ויצירת ה־Embeddings נכשלה. אחרי הכשל, הקובץ כבר לא היה באינדקס כלל.

**הגורם:** העדכון מחק את המקטעים הישנים של הקובץ **לפני** שהגרסה החדשה נשמרה. כשהשלב השני נכשל, לא נשארה אף גרסה.

**הפתרון:** עדכון בטוח בשלושה שלבים:
1. יצירת הגרסה החדשה ושמירתה, בלי לגעת בגרסה הישנה.
2. כתיבה אטומית של קובץ ה־manifest – רק כאן הגרסה החדשה הופכת לרשמית.
3. מחיקת הגרסה הישנה.

בנוסף, בכל טעינה רצה בדיקת התאוששות מקומית שמנקה שאריות של עדכון שנקטע. בדיקות אוטומטיות מדמות כשל בכל אחד מהשלבים, ובכולן שאר המסמכים נשארים בדיוק כפי שהיו.
