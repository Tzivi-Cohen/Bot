Arduino – תקשורת טורית (Serial)
================================

הערה: הפרטים מתייחסים ל־Arduino UNO R3. בלוחות אחרים (Mega, Leonardo, ‏ESP32 ועוד) מספר יציאות ה־Serial, הפינים והתנהגות ה־USB שונים.

1. מה זה Serial?
-----------------
Serial היא תקשורת טורית אסינכרונית (UART): הנתונים נשלחים ביט אחרי ביט על קו אחד, בלי קו שעון משותף. שני הצדדים חייבים להסכים מראש על קצב השידור (Baud Rate).
ב־UNO, היציאה Serial משתמשת בפינים 0 (RX) ו־1 (TX), ובמקביל היא עוברת דרך שבב USB-to-Serial שעל הלוח למחשב. לכן:
- לא כדאי לחבר רכיבים לפינים 0 ו־1 בזמן שמשתמשים ב־Serial Monitor או מעלים Sketch.
- ב־Serial Monitor של Arduino IDE בוחרים את אותו Baud Rate שהוגדר בקוד.

2. שליחת נתונים למחשב
----------------------
    void setup() {
      Serial.begin(9600);          // Baud Rate – 9600 ביט לשנייה
    }

    void loop() {
      int value = analogRead(A0);
      Serial.print("A0 = ");       // בלי ירידת שורה
      Serial.println(value);       // עם ירידת שורה
      delay(500);
    }

- Serial.print(x) – מדפיסה ערך כטקסט.
- Serial.println(x) – מדפיסה ומוסיפה ירידת שורה (‎\r\n).
- Serial.print(x, HEX) / Serial.print(x, BIN) – הדפסה בבסיס 16 או 2.
- Serial.print(3.14159, 3) – הדפסת מספר עשרוני עם 3 ספרות אחרי הנקודה. ברירת המחדל היא 2.
- Serial.write(b) – שולחת בית בודד כמו שהוא (Raw), בלי להמיר לטקסט.

קצבים נפוצים: 9600, 57600, 115200. קצב גבוה יותר מעביר יותר נתונים, אבל רגיש יותר לשגיאות תזמון ולחוטים ארוכים.

3. Serial Plotter
------------------
ה־Serial Plotter של Arduino IDE מצייר גרף של מספרים שמודפסים בשורות. כדי להציג כמה גרפים יחד, מדפיסים כמה ערכים באותה שורה, מופרדים ברווח או בפסיק:

    Serial.print(analogRead(A0));
    Serial.print(",");
    Serial.println(analogRead(A1));

4. קבלת נתונים מהמחשב
----------------------
- Serial.available() – מחזירה כמה בתים ממתינים ב־Buffer של הקבלה.
- Serial.read() – קוראת בית אחד. מחזירה ‎-1 אם אין נתונים.

דוגמה: שליטה בנורה באמצעות פקודות של תו אחד:

    void setup() {
      Serial.begin(9600);
      pinMode(LED_BUILTIN, OUTPUT);
    }

    void loop() {
      if (Serial.available() > 0) {
        char c = Serial.read();
        if (c == '1') {
          digitalWrite(LED_BUILTIN, HIGH);
          Serial.println("LED ON");
        } else if (c == '0') {
          digitalWrite(LED_BUILTIN, LOW);
          Serial.println("LED OFF");
        }
        // תווים אחרים (למשל ירידת שורה) – מתעלמים
      }
    }

5. קריאת שורה שלמה בלי לחסום את הלולאה
---------------------------------------
Serial.readStringUntil('\n') ו־Serial.parseInt() נוחות, אבל הן ממתינות עד שמגיע התו המבוקש או עד שעובר Timeout (ברירת המחדל: 1000ms). בזמן הזה הלולאה עוצרת.
גישה שאינה חוסמת: צוברים תווים ל־Buffer עד שמגיע תו סוף שורה:

    const byte MAX_LEN = 32;
    char line[MAX_LEN];
    byte len = 0;

    void loop() {
      while (Serial.available() > 0) {
        char c = Serial.read();
        if (c == '\n') {
          line[len] = '\0';           // סיום מחרוזת
          handleCommand(line);
          len = 0;
        } else if (c != '\r' && len < MAX_LEN - 1) {
          line[len++] = c;            // מגינים מפני גלישה מה־Buffer
        }
      }
      // שאר הקוד ממשיך לרוץ
    }

    void handleCommand(const char* cmd) {
      if (strcmp(cmd, "status") == 0) {
        Serial.println("OK");
      } else if (strncmp(cmd, "pwm ", 4) == 0) {
        int v = atoi(cmd + 4);
        analogWrite(9, constrain(v, 0, 255));
      } else {
        Serial.println("Unknown command");
      }
    }

ב־Serial Monitor בוחרים "Newline" כסיום שורה, כדי שכל פקודה תסתיים ב־'\n'.

6. Buffer ושליחה
-----------------
ל־Serial יש Buffer קבלה בגודל מוגבל. ב־UNO הוא 64 בתים כברירת מחדל בליבה הסטנדרטית. אם הקוד לא קורא מספיק מהר, בתים חדשים יאבדו.
Serial.print אינה ממתינה בדרך כלל לסיום השידור: הנתונים נכנסים ל־Buffer שליחה ונשלחים ברקע. כשה־Buffer מלא, הפונקציה כן ממתינה. Serial.flush() ממתינה עד שכל הנתונים נשלחו בפועל.

7. תקשורת בין שני לוחות
------------------------
מחברים TX של לוח אחד ל־RX של השני, RX ל־TX, ו־GND ל־GND. בלי GND משותף אין מתח ייחוס משותף, והתקשורת לא תעבוד.
אם לוח אחד עובד ב־5V והשני ב־3.3V, צריך התאמת רמות (Level Shifter) לפחות בכיוון 5V→3.3V, כדי לא לפגוע בלוח של 3.3V.
ב־UNO יש יציאת UART חומרתית אחת בלבד. אפשר להוסיף יציאה בתוכנה עם הספרייה SoftwareSerial, בקצבים נמוכים יחסית.

8. מבנה מסגרת UART (בקצרה)
---------------------------
במצב ברירת המחדל של Arduino ‏(8N1), כל בית נשלח כך: ביט התחלה (Start, ‏0), שמונה ביטי נתונים מהביט הפחות משמעותי (LSB) ראשון, בלי ביט זוגיות (Parity), וביט עצירה אחד (Stop, ‏1). כשהקו פנוי (Idle) הוא נמצא ב־HIGH. סך הכול נשלחים 10 ביטים לכל בית, ולכן ב־9600 Baud מועברים לכל היותר כ־960 בתים בשנייה.

9. שאלות תרגול ופתרונות
------------------------
שאלה 1: ב־Serial Monitor מופיעים תווים משובשים. מה הסיבה הסבירה?
פתרון: ה־Baud Rate ב־Serial Monitor שונה מהערך שהוגדר ב־Serial.begin(). צריך לבחור בשני הצדדים את אותו קצב.

שאלה 2: כמה בתים בשנייה אפשר להעביר לכל היותר ב־115200 Baud במצב 8N1?
פתרון: כ־11,520 בתים בשנייה, כי כל בית דורש 10 ביטים: 115200 / 10 = 11520.

שאלה 3: למה לא כדאי להשתמש ב־delay(1000) בלולאה שצריכה לקבל פקודות מהמחשב?
פתרון: במשך השנייה הזו הקוד לא קורא מה־Buffer. אם יגיעו יותר בתים מגודל ה־Buffer, חלקם יאבדו, והתגובה לפקודות תתעכב.

שאלה 4: חיברתם שני לוחות UNO עם TX ל־RX ו־RX ל־TX, אבל לא מתקבלים נתונים. מה כדאי לבדוק קודם?
פתרון: שיש חיבור GND משותף בין הלוחות, שה־Baud Rate זהה בשני הצדדים, ושפינים 0 ו־1 אינם תפוסים בזמן ההעלאה או בשימוש של ה־Serial Monitor.
