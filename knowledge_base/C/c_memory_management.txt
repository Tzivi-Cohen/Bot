C – ניהול זיכרון (Memory Management)
=====================================

1. אזורי הזיכרון של תוכנית C
-----------------------------
בתוכנית C טיפוסית יש כמה אזורי זיכרון:
- Text (Code) – קוד התוכנית עצמו. במיקרו־בקרים הוא נמצא בדרך כלל בזיכרון Flash.
- Data – משתנים גלובליים ו־static שאותחלו בערך שונה מאפס.
- BSS – משתנים גלובליים ו־static שלא אותחלו, או שאותחלו לאפס. הם מאופסים לפני main.
- Stack (מחסנית) – משתנים מקומיים, פרמטרים וכתובות חזרה מפונקציות. הזיכרון מוקצה ומשוחרר אוטומטית בכניסה וביציאה מפונקציה.
- Heap (ערימה) – זיכרון שמוקצה ידנית בזמן ריצה עם malloc ומשוחרר עם free.

2. הקצאה דינמית: malloc, calloc, realloc, free
-----------------------------------------------
הפונקציות מוגדרות ב־<stdlib.h>.

    #include <stdio.h>
    #include <stdlib.h>

    int main(void) {
        size_t n = 5;
        int *arr = malloc(n * sizeof *arr);    /* הקצאה של 5 int */
        if (arr == NULL) {                      /* חובה לבדוק! */
            fprintf(stderr, "Out of memory\n");
            return 1;
        }
        for (size_t i = 0; i < n; i++) {
            arr[i] = (int)(i * i);
        }
        free(arr);        /* שחרור */
        arr = NULL;       /* מונע שימוש חוזר בטעות */
        return 0;
    }

- malloc(size) – מקצה size בתים. התוכן לא מאותחל.
- calloc(count, size) – מקצה count * size בתים ומאפס אותם.
- realloc(ptr, new_size) – משנה את גודל ההקצאה. עשוי להעביר את הנתונים לכתובת חדשה, ולכן משתמשים בערך שהוא מחזיר. אם הוא נכשל הוא מחזיר NULL, וההקצאה המקורית נשארת בתוקף.
- free(ptr) – משחרר הקצאה. free(NULL) הוא פעולה חוקית שלא עושה כלום.

שימוש נכון ב־realloc:
    int *tmp = realloc(arr, 2 * n * sizeof *arr);
    if (tmp == NULL) {
        /* arr עדיין תקף – אפשר לטפל בשגיאה בלי לאבד אותו */
    } else {
        arr = tmp;
        n *= 2;
    }

הטעות הנפוצה: arr = realloc(arr, ...) – אם realloc נכשלת, arr הופך ל־NULL והזיכרון המקורי "אובד" (Memory Leak).

3. שגיאות זיכרון נפוצות
------------------------
- Memory Leak – זיכרון שהוקצה ולא שוחרר. בתוכנית שרצה זמן רב (כמו קושחה) הזיכרון הפנוי הולך ואוזל.
- Dangling Pointer – שימוש במצביע אחרי free. זה Undefined Behavior.
- Double Free – שחרור של אותה הקצאה פעמיים. זה Undefined Behavior.
- Buffer Overflow – כתיבה מעבר לגודל ההקצאה.
- החזרת כתובת של משתנה מקומי:

    int *bad(void) {
        int local = 5;
        return &local;   /* שגוי! local נעלם כשהפונקציה מסתיימת */
    }

כלים לאיתור שגיאות זיכרון במחשב: Valgrind (Linux), ו־AddressSanitizer (הדגל ‎-fsanitize=address ב־GCC וב־Clang).

4. Stack מול Heap – מתי להשתמש במה?
------------------------------------
- Stack: מהיר מאוד ומשתחרר אוטומטית, אבל מוגבל בגודלו. מערך מקומי גדול (למשל int big[1000000]) עלול לגרום ל־Stack Overflow.
- Heap: מתאים לנתונים שגודלם ידוע רק בזמן ריצה, או שצריכים להתקיים אחרי סיום הפונקציה. דורש free ידני, והקצאה ושחרור חוזרים עלולים לגרום לפיצול זיכרון (Fragmentation).

5. הקצאה דינמית במערכות משובצות
--------------------------------
בקושחה למיקרו־בקרים נוטים להימנע מ־malloc ו־free, או להגביל את השימוש בהם לשלב האתחול בלבד. הסיבות:
- זיכרון ה־RAM קטן, ופיצול עלול לגרום לכישלון הקצאה אחרי זמן ריצה ארוך.
- זמן הריצה של malloc לא תמיד צפוי, וזה בעייתי במערכות זמן אמת.
- תקני קוד כמו MISRA C מגבילים שימוש בהקצאה דינמית.
חלופות: הקצאה סטטית (מערכים גלובליים בגודל קבוע), ו־Memory Pools – מאגרים של בלוקים בגודל קבוע.

6. דוגמה: מערך דינמי שגדל (Dynamic Array)
-----------------------------------------
    typedef struct {
        int *data;
        size_t size;
        size_t capacity;
    } IntVector;

    int vec_push(IntVector *v, int value) {
        if (v->size == v->capacity) {
            size_t new_cap = (v->capacity == 0) ? 4 : v->capacity * 2;
            int *tmp = realloc(v->data, new_cap * sizeof *tmp);
            if (tmp == NULL) return -1;     /* כישלון – הנתונים הקיימים נשמרו */
            v->data = tmp;
            v->capacity = new_cap;
        }
        v->data[v->size++] = value;
        return 0;
    }

    void vec_free(IntVector *v) {
        free(v->data);
        v->data = NULL;
        v->size = v->capacity = 0;
    }

    /* שימוש: IntVector v = {0}; vec_push(&v, 10); ... vec_free(&v); */

הכפלת הקיבולת בכל הגדלה נותנת זמן ממוצע קבוע להוספה (Amortized O(1)).

7. sizeof ושימוש נכון בו
-------------------------
- הכתיבה malloc(n * sizeof *ptr) עדיפה על malloc(n * sizeof(int)): אם הטיפוס של ptr ישתנה, הביטוי יישאר נכון.
- ב־C אין צורך בהמרה (Cast) של הערך ש־malloc מחזירה, כי void * מומר אוטומטית. ב־C++ ההמרה נדרשת, אבל שם עדיף להשתמש ב־new או בקונטיינרים.

8. שאלות תרגול ופתרונות
------------------------
שאלה 1: מה ההבדל בין malloc ל־calloc?
פתרון: malloc מקבלת מספר בתים ולא מאתחלת את התוכן. calloc מקבלת מספר איברים וגודל איבר, ומאפסת את כל הזיכרון.

שאלה 2: מצאו את הבאג:
    char *copy(const char *src) {
        char *dst = malloc(strlen(src));
        strcpy(dst, src);
        return dst;
    }
פתרון: יש שני באגים. ראשית, חסר בית אחד לתו '\0', כך שצריך strlen(src) + 1. שנית, אין בדיקה ש־malloc לא החזירה NULL.

שאלה 3: למה כדאי להציב NULL במצביע אחרי free?
פתרון: כדי ששימוש חוזר בטעות יתגלה בבדיקת NULL, או יגרום לקריסה ברורה במקום להשחית זיכרון בשקט. בנוסף, free(NULL) חוקי, ולכן שחרור כפול של מצביע שאופס לא יגרום נזק.

שאלה 4: מדוע מערך מקומי של מיליון int עלול לגרום לקריסה, ומה הפתרון?
פתרון: מערך כזה תופס כ־4MB (כאשר int הוא 4 בתים), וזה יותר מגודל המחסנית הטיפוסי. הפתרון הוא הקצאה ב־Heap עם malloc, או הגדרה כ־static או גלובלי.
