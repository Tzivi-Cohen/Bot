אלגוריתמים – מיון וחיפוש (Sorting and Searching)
=================================================

1. חיפוש לינארי (Linear Search)
--------------------------------
עוברים על האיברים אחד אחד עד שמוצאים את הערך. הסיבוכיות היא O(n). החיפוש עובד גם על נתונים לא ממוינים.

    def linear_search(items, target):
        for i, value in enumerate(items):
            if value == target:
                return i
        return -1

2. חיפוש בינארי (Binary Search)
--------------------------------
חיפוש בינארי עובד רק על מערך ממוין. בכל שלב משווים לאיבר האמצעי ומצמצמים את טווח החיפוש לחצי, ולכן הסיבוכיות היא O(log n). במערך של מיליון איברים נדרשות לכל היותר כ־20 השוואות, כי 2^20 ≈ 1,048,576.

    def binary_search(items, target):
        low, high = 0, len(items) - 1
        while low <= high:
            mid = (low + high) // 2
            if items[mid] == target:
                return mid
            if items[mid] < target:
                low = mid + 1
            else:
                high = mid - 1
        return -1

    binary_search([2, 5, 8, 12, 16, 23, 38], 23)   # 5

ב־C וב־Java מחשבים את האמצע כ־low + (high - low) / 2, כדי למנוע גלישה (Overflow) של low + high כשהמספרים גדולים. ב־Python אין בעיה כזו, כי int אינו מוגבל בגודלו.
ב־Python יש את המודול bisect, שמוצא נקודת הכנסה במערך ממוין: bisect.bisect_left(items, x).

3. מיונים פשוטים – O(n^2)
--------------------------
מיון בועות (Bubble Sort): עוברים שוב ושוב על המערך ומחליפים זוגות סמוכים שאינם בסדר. אחרי כל מעבר, האיבר הגדול ביותר שנותר "מבעבע" לסוף.

    def bubble_sort(a):
        n = len(a)
        for i in range(n - 1):
            swapped = False
            for j in range(n - 1 - i):
                if a[j] > a[j + 1]:
                    a[j], a[j + 1] = a[j + 1], a[j]
                    swapped = True
            if not swapped:      # אין החלפות – המערך כבר ממוין
                break
        return a

מיון הכנסה (Insertion Sort): בונים חלק ממוין משמאל, וכל איבר חדש מוכנס למקומו הנכון בתוכו. המיון יעיל למערכים קטנים או כמעט ממוינים, שם הוא קרוב ל־O(n) במקרה הטוב.

    def insertion_sort(a):
        for i in range(1, len(a)):
            key = a[i]
            j = i - 1
            while j >= 0 and a[j] > key:
                a[j + 1] = a[j]
                j -= 1
            a[j + 1] = key
        return a

מיון בחירה (Selection Sort): בכל שלב בוחרים את המינימום מהחלק הלא ממוין ומעבירים אותו לסוף החלק הממוין. המיון מבצע O(n^2) השוואות תמיד, אבל רק O(n) החלפות.

4. מיון מיזוג (Merge Sort) – O(n log n)
----------------------------------------
אלגוריתם "הפרד ומשול" (Divide and Conquer): מחלקים את המערך לשני חצאים, ממיינים כל חצי ברקורסיה, וממזגים את שני החצאים הממוינים.

    def merge_sort(a):
        if len(a) <= 1:
            return a
        mid = len(a) // 2
        left = merge_sort(a[:mid])
        right = merge_sort(a[mid:])
        merged, i, j = [], 0, 0
        while i < len(left) and j < len(right):
            if left[i] <= right[j]:      # <= שומר על יציבות
                merged.append(left[i]); i += 1
            else:
                merged.append(right[j]); j += 1
        merged.extend(left[i:])
        merged.extend(right[j:])
        return merged

    merge_sort([38, 27, 43, 3, 9, 82, 10])   # [3, 9, 10, 27, 38, 43, 82]

תכונות:
- O(n log n) בכל המקרים: טוב, ממוצע וגרוע.
- דורש O(n) זיכרון נוסף.
- יציב.

5. מיון מהיר (Quick Sort)
--------------------------
בוחרים איבר ציר (Pivot), מחלקים את המערך לאיברים קטנים מהציר ולאיברים גדולים ממנו (Partition), וממיינים כל חלק ברקורסיה.

    def quick_sort(a):
        if len(a) <= 1:
            return a
        pivot = a[len(a) // 2]
        less = [x for x in a if x < pivot]
        equal = [x for x in a if x == pivot]
        greater = [x for x in a if x > pivot]
        return quick_sort(less) + equal + quick_sort(greater)

(גרסה זו נכתבה לשם הבהירות ומשתמשת בזיכרון נוסף. במימוש המקובל, החלוקה מתבצעת בתוך המערך עצמו – In-Place.)

תכונות:
- ממוצע O(n log n), ובפועל מהיר מאוד.
- במקרה הגרוע O(n^2) – למשל כשהציר הוא תמיד האיבר הקטן ביותר. בחירת ציר אקראי, או חציון של שלושה איברים, מקטינה את הסיכוי לכך.
- במימוש In-Place דורש רק O(log n) זיכרון מחסנית בממוצע.
- אינו יציב במימוש In-Place הרגיל.

6. יציבות מיון (Stability)
---------------------------
מיון יציב (Stable) שומר על הסדר המקורי בין איברים שווים. זה חשוב כשממיינים לפי מפתח אחד אחרי שכבר מיינו לפי מפתח אחר. למשל: מיינו קודם לפי שם ואחר כך, במיון יציב, לפי ציון – בעלי אותו ציון יישארו ממוינים לפי שם.
יציבים: Merge Sort, Insertion Sort, Bubble Sort.
לא יציבים במימוש הרגיל: Quick Sort, Selection Sort, Heap Sort.
הפונקציה sorted של Python והמתודה list.sort משתמשות באלגוריתם Timsort, שהוא יציב ומבצע O(n log n) במקרה הגרוע.

7. טבלת סיכום
--------------
| אלגוריתם       | טוב        | ממוצע      | גרוע       | זיכרון נוסף | יציב |
| Bubble Sort    | O(n)       | O(n^2)     | O(n^2)     | O(1)        | כן   |
| Insertion Sort | O(n)       | O(n^2)     | O(n^2)     | O(1)        | כן   |
| Selection Sort | O(n^2)     | O(n^2)     | O(n^2)     | O(1)        | לא   |
| Merge Sort     | O(n log n) | O(n log n) | O(n log n) | O(n)        | כן   |
| Quick Sort     | O(n log n) | O(n log n) | O(n^2)     | O(log n)    | לא   |
| Heap Sort      | O(n log n) | O(n log n) | O(n log n) | O(1)        | לא   |
(הערך O(n) במקרה הטוב של Bubble Sort נכון רק עם בדיקת "אין החלפות", כמו בקוד שבסעיף 3.)

חסם תחתון: כל מיון שמבוסס על השוואות בלבד דורש Ω(n log n) השוואות במקרה הגרוע. מיונים שאינם מבוססים על השוואות, כמו Counting Sort ו־Radix Sort, יכולים להגיע ל־O(n) על סוגי נתונים מסוימים, למשל מספרים שלמים בטווח מוגבל.

8. שאלות תרגול ופתרונות
------------------------
שאלה 1: כמה השוואות לכל היותר נדרשות לחיפוש בינארי במערך ממוין של 1000 איברים?
פתרון: 10, כי 2^10 = 1024 ≥ 1000. בכל השוואה הטווח קטן בערך לחצי.

שאלה 2: אילו שלבים יעבור המערך [5, 1, 4, 2] במעבר הראשון של Bubble Sort?
פתרון: [1, 5, 4, 2] → [1, 4, 5, 2] → [1, 4, 2, 5]. בסוף המעבר הראשון, 5 (הגדול ביותר) נמצא בסוף.

שאלה 3: מתי עדיף Insertion Sort על Quick Sort?
פתרון: במערכים קטנים מאוד, או כשהמערך כמעט ממוין. שם Insertion Sort קרוב ל־O(n), והתקורה שלו נמוכה. מסיבה זו מימושים רבים של מיונים מהירים עוברים ל־Insertion Sort כשתת־המערך קטן.

שאלה 4: למה אי אפשר להשתמש בחיפוש בינארי ברשימה מקושרת ביעילות?
פתרון: חיפוש בינארי צריך גישה ישירה לאיבר האמצעי ב־O(1). ברשימה מקושרת הגישה לאמצע היא O(n), ולכן היתרון של החיפוש הבינארי אובד.
